# Summon on the Mac: settings, configs, themes, rules

You were summoned onto this Mac. Summon is an agent layer for macOS: one agent (you)
that can be called from anywhere, one CLI that describes everything, one theme that restyles
everything, and a checkpoint before every session so whatever you do can be undone.

## First moves

```bash
summon commands --json      # every Summon command: summary, args, examples, risk
macctl list --json          # every Mac setting macctl knows, with its current value
macctl doctor               # permissions and what is missing
summon checkpoint list      # what earlier sessions changed
summon context              # this Mac: hardware, power, storage, network, displays, apps, permissions (start here)
summon status --json        # agent, macctl health, last change, last checkpoint, recent crashes
summon doctor --json        # Summon's own install: app, CLI, config, macctl, event log, hotkeys, skill links; each check has a fix
summon events --limit 20    # timeline: settings changes and undos, checkpoints, sessions, themes, crashes
```

Read a command's help before running it (`summon <group> <cmd> --help` never executes anything).

## The session block in your prompt

When Summon starts you with a task, the prompt ends with a `## Summon session` block. It is the truth about
this run; use it instead of guessing:

- **Checkpoint id** and the exact undo command (`summon checkpoint undo <id>`). "No checkpoint" means nothing is
  undoable through Summon: ask before every change. "Incomplete" means treat changes as hard to undo.
- **Approval mode.** *Unattended*: your tool calls run without prompts, so these rules are the only check.
  *Harness controls*: your harness asks the user before risky calls; the rules still apply.
- **Scheduled task**: nobody is watching. Never ask or wait; skip what needs a person and say so in the final
  summary, which is all the user reads.
- **Working folder** and the **skill files** chosen for you (read them if your harness has no skill mechanism).

A session started from the hotkey or menu with no task has no block: the checkpoint is still taken; find it with
`summon checkpoint list`.

## Rules

1. **Settings go through `macctl`, never raw `defaults write` / `osascript`** for anything `macctl` covers.
   `macctl` snapshots the old value and can `undo`. If a setting is missing from `macctl list`, say so,
   do it the raw way only if the user agrees, and note the exact command in your summary so it can be added.
2. **Edit configs in `~/.config`, never the shipped copies.** Summon's defaults live in its install
   folder (`$(summon path)`); copy before you customize. Generated files under `~/.config/summon/current/`
   are overwritten on every `summon theme set`: change the theme JSON instead.
3. **Stay inside the checkpoint.** Summon took one when this session started (`macctl` snapshot + a git commit of
   `~/.config`). Whether your tool calls are approved for you or prompted depends on the mode in the session block;
   either way, things outside the checkpoint, such as deleting files outside `~/.config`, uninstalling apps,
   changing login passwords, sending anything off this Mac, or anything under `/System`, need the user's explicit
   yes first.
4. **Admin steps** use `sudo` in the visible terminal (Touch ID if `pam_tid` is on). Never write passwords
   to files, never `sudo -S` with a piped password, never edit `/etc/sudoers`.
5. **Report what you changed** at the end: settings (ids and old → new), files, apps installed, and how to
   undo (`summon checkpoint undo <id>` with the id from the session block, `summon undo-session` for the latest,
   or `macctl undo <snapshot>` for one setting).

## Where things live

| Thing | Location | Tool |
|---|---|---|
| macOS settings | defaults domains | `macctl get/set/apply/undo` |
| Theme | `~/.config/summon/themes/<slug>/theme.json` (user) or shipped `themes/` | `summon theme list`, `summon theme set <slug>` |
| Current theme output | `~/.config/summon/current/` (ghostty.conf, borders.env, claude-theme.json) | regenerated by `theme set` |
| Wallpaper | per theme `wallpapers` list | `summon theme set <slug>` or `macctl set desktop.wallpaper <path>` |
| Tiling | `~/.config/aerospace/aerospace.toml` | `aerospace reload-config` |
| Terminal | `~/.config/ghostty/config` (`config-file = ~/.config/summon/generated/ghostty.conf`); kitty: `~/.config/kitty/kitty.conf` (`include ~/.config/summon/generated/kitty.conf`) | Ghostty reloads on save (⌘⇧,); kitty: ⌃⌘, |
| Terminal agents open in | `~/.config/summon/defaults/terminal` | `summon default terminal ghostty\|kitty\|terminal` |
| Window borders | `~/.config/borders/bordersrc` | `brew services restart borders` |
| Summon Menu | `~/.config/summon/menu.jsonc` | `summon menu summon <id>` |
| Hooks | `~/.config/summon/hooks/<event>.d/` (theme-set, post-login, post-update, wake, battery-low) | `summon hooks run <event>` |
| Apps | `~/.config/summon/Brewfile` | `brew bundle --file ~/.config/summon/Brewfile` |
| Everything agents make | `~/Summon`: `Apps/<name>`, `Art/<job>`, `Tasks/<id>`, `Themes` (a link to the themes) | `summon home` |
| Default agent | `~/.config/summon/defaults/agent` | `summon default agent <name>` |
| Per-agent model and skills | `~/.config/summon/agents.json` | `summon agents set <agent> --model <m> --skills a,b` |
| Recurring agent tasks | `~/.config/summon/tasks.json`, logs in `~/Summon/Tasks/<id>/` | `summon task add "<prompt>" --at 09:00 [--weekdays] \| --every 2h [--agent <id>]`, `task list`, `task run <id>`, `task remove <id>` |

## Making a new theme

Copy a theme folder to `~/.config/summon/themes/<slug>/`, edit `theme.json` (name, slug, appearance,
colors, 16 terminal colors, font, wallpapers), check contrast: foreground on background ≥ 4.5:1 (aim for 7:1). `muted` and `selection` are for borders,
inactive outlines and backgrounds, never body text, so they only need to be visible (about 1.5:1).
Then `summon theme check <slug>` until it prints "valid" (theme list skips a theme that fails), then `summon theme set <slug>`. Wallpapers: 5120×2880 JPEG next to `theme.json`.

**Palette, wallpaper, icons, any image: use the `summon-art` skill** (`$(summon path)/skills/summon-art/SKILL.md`).
Mood → three concepts → palette from the subject (contrast checked) → images generated with Nano Banana → reviewed
→ the user picks → installed. Never ship a plain gradient or a default palette when the user asked for something nice.

## Recurring tasks

The user describes what they want ("every weekday at 9, check brew updates and tell me what is outdated");
you turn it into a task. It will run **unattended**: no chat, nobody to answer questions, in `~/Summon`, after a
checkpoint, for at most 30 minutes.

1. Ask only what you cannot infer: when (map "mornings" to a time, "work days" to `--weekdays`), which agent
   (default if unsaid; `summon agents` lists them), and what the user wants to see afterwards.
2. Write the run prompt as a complete brief: what to check or do, where, what never to touch (nothing destructive
   without the user), and end with "Finish with a short summary of what you found or changed." That summary is
   what the user reads in Activity and in the result notification. Summon wraps every run with the unattended
   rules and the session block, so do not repeat them.
3. `summon task add "<run prompt>" --at HH:MM [--weekdays] | --every <n>h [--agent <id>] --name "<short name>"`
4. Show `summon task list`, offer `summon task run <id>` to try it now, and say how to stop it:
   `summon task remove <id>`. Logs: `~/Summon/Tasks/<id>/`. Each run ends with a "Task done" or "Task failed"
   notification (Show Log, Ask Agent).

## Keybindings (default)

| Keys | Does |
|---|---|
| ⌃⌥Space | Summon panel with the Summon Menu (also `summon panel`) |
| ⌃⌥⌘A | Summon the agent in a new terminal |
| ⌃⌥⌘\` | Drop-down terminal (Ghostty quick terminal); type `a` for the agent |
| ⌥1…9 / ⌥⇧1…9 | Go to / move window to workspace |
| ⌥H J K L / ⌥⇧H J K L | Focus / move window |
| ⌥Return | New Ghostty window |
| ⌥⇧F / ⌥⇧W | Fullscreen / close window; ⌥⇧Space float toggle |

Change them in `aerospace.toml` (window keys) and Summon's Settings window (⌃⌥Space, ⌃⌥⌘A).

## Building something new

Menu bar apps, full apps, screensavers and icons follow the `mac-app` skill. Use it for any "make me an app".

## When something is broken

Logs: `mac-logs` skill. Crashes: `diagnose-crash-mac` skill. A vague "my Mac is acting up": start with
`summon debug --print --since 1h`.
